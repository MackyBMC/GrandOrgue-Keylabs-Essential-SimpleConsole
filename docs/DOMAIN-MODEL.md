# Domain model and glossary

*Status: PROPOSED (terms) / VERIFIED (where a term names an existing v2 structure).*

## Ubiquitous language
| Term | Meaning |
|------|---------|
| **Organ** | One instrument description: divisions, stops, couplers, tremulants, expression, with a stable `organ_id`. |
| **Division** | A group of stops on one keyboard or the pedal (Pedal, Hauptwerk, Schwellwerk, Solowerk in Friesach). v2: `DIVISIONS`. |
| **Manual** | A keyboard of the organ (the pedal is a manual in GrandOrgue's numbering). The number of manuals is **a property of the organ**, not fixed at four. |
| **Stop** | A switchable rank or group of ranks. v2: `Item(kind="stop")`. |
| **Coupler** | Connects divisions. v2: `Item(kind="coupler")`. |
| **Tremulant** | Tremulant switch. v2: `Item(kind="tremulant")`. |
| **Expression / swell** | Continuous control of a division. |
| **Logical ID** | Stable, engine-independent identifier: `organ_id` + division id + stop id (slug derived from the organ data, never from a wire number). |
| **Wire address** | An engine's own address for a control: GrandOrgue object path, CC number, MIDI channel. Owned by the engine adapter. |
| **Registration** | A set of logical stop/coupler/tremulant states. |
| **Setter / combination** | A named registration file (one YAML per piece in v2) with ordered **steps** (000-0xx). |
| **Step** | One registration state inside a setter, advanced with `>>` / `<<`. |
| **Bank** | A group of up to `BANK_SIZE` (8) controls mapped to the controller's faders. A controller concept derived from division/stop counts and the controller's fader count. |
| **Take** | A recorded or loaded MIDI performance with its setter changes. |
| **Session** | The live state: current organ, loaded setter file and step, tempo, loaded take, controller engaged. |
| **Track / voice mapping** | Assignment of score tracks/voices to manuals, many-to-one, with registrations changeable by bar (`track_map` in v2). |
| **Engine** | The thing that makes sound: GrandOrgue, Aeolus, a VST3/CLAP host. |
| **Controller** | The thing the player touches: KeyLab, others. |
| **Adapter / plugin** | Code that implements the Engine or Controller contract. |
| **Capability** | A declared feature of an engine or controller (e.g. `state_readback`, `faders=8`, `lcd=2x16`). |

## Logical organ model (PROPOSED shape)
```yaml
organ_id: friesach-parish
name: Friesach Parish Church
manuals:                      # ordered; count and names come from here
  - {id: pedal,  name: Pedal,       midi_role: pedal}
  - {id: great,  name: Hauptwerk}
  - {id: swell,  name: Schwellwerk, expression: true}
  - {id: solo,   name: Solowerk}
stops:
  - {id: pedal.untersatz-32, manual: pedal, name: "Untersatz 32'", lcd: "Untersatz 32'"}
couplers:
  - {id: coupler-1, name: "Coupler 1 (ped)", from: great, to: pedal}
tremulants:
  - {id: tremolo-2, name: "Tremolo II", division: swell}
engine_hints:                 # optional, per engine, written by that engine's importer
  grandorgue: {source: "Friesach FullImageResolution.organ"}
```
The GrandOrgue **wire map** (path per control, CC/channel assignment, switch offsets, the Friesach tremulant quirks) is generated by the GrandOrgue plugin from the `.organ` file and kept beside the organ data, never in the logical section.

## Identity rules
- A logical ID never contains a wire number, a channel, or an engine path.
- IDs are stable across re-imports of the same organ; renaming a stop's display name does not change its ID.
- v2 setter YAML (GrandOrgue object paths) is migrated to logical IDs by a one-way, backed-up migration; the original markers remain readable (GUARDRAILS I-3, I-4).

## Mapping from v2 structures
| v2 | v3 concept |
|----|------------|
| `DIVISIONS`, `OTHERS` | organ data: manuals, stops, couplers, tremulants |
| `Item.cc/channel/key/path` | engine wire map (GrandOrgue plugin) |
| `Item.bank_code/division` | controller banking derived from the model |
| `sessionmeta.MANUALS` (4 fixed slots, channels 2-5) | organ's manuals + a per-engine channel/role assignment |
| `Stave.track_map`, `voice_reg` | session track/voice mapping stored by logical id |
